# 구현: 작은 기능과 검증 루프

전제: START.md 분석 결과와 사용자의 핵심 선택을 확인했다. RULES.md를 준수한다.
핵심 선택이 미확정이면 필요한 선택만 먼저 확인한다.

1. 지금 구현할 기능과 완료 조건을 한두 문장으로 확인한다.
2. 작은 사례의 기대 결과를 요구사항에서 정한다. 아직 만든 코드의 결과를 정답으로 삼지 않는다.
3. 기존 기술 스택과 파일 구조를 활용한다. 먼저 실제 입력이 최종 출력까지 연결되는 최소 기능을 만든다.
4. 필요한 범위만 변경한다. UI 작업은 승인된 데이터 계약과 계산 로직을 바꾸지 않는다.
5. 허용된 테스트/실행 명령을 사용한다. 원본 자료를 변경하지 않고 안전한 임시 입력을 사용한다.
6. 실패하면 실제 출력과 원인을 확인하고 최소 수정한 뒤 동일 사례와 회귀 테스트를 실행한다.
7. 주요 기능 단위로 다음 내용을 짧게 보고한다.
   - 실제 파일/함수와 변경 내용
   - 작은 입력 → 중간 처리 → 출력
   - 선택 이유와 한계
   - 실행 명령, 기대 결과, 실제 결과, 미검증 항목
8. 중요한 데이터 처리, 핵심 계산, 통합 완료 같은 단계에서 사용자의 이해 점검을 제안한다.
   사소한 수정마다 멈추지 않는다. 승인 범위 밖의 결정이 필요하면 멈춘다.

빈 화면을 예시 데이터만으로 꾸미고 완성이라고 하지 않는다.
새 기능을 늘리기 전에 필수 기능이 실제로 동작하는지 확인한다.
검증을 통과하기 위해 요구사항을 느슨하게 해석하거나 숨은 수요/행을 버리지 않는다.
